Troubleshooting, caveats, and next steps

Most early problems are not sophisticated neuroscience problems. They are version mismatch, wrong host/port, wrong channel labels, missing events, buffer resets, or an assumption that software timestamps equal physical onset.

Common symptoms

SymptomFirst checks
MATLAB cannot connectIs the bridge running? Is acquisition in Go? Is the host correct? Is port 1972 reachable? Is a firewall blocking it?
Header is empty or staleConfirm the bridge and acquisition status; restart only according to local operator procedure; check whether the buffer was reset.
Data appear in large burstsInspect chunk size and actual update cadence. Do not assume a requested chunk size is the delivered cadence.
Wrong channel appearsPrint all labels from the header. Confirm channel order and auxiliary channel labels in the current acquisition configuration.
Events are missingConfirm the trigger is physically connected and configured; inspect the raw recording and FieldTrip event list.
Loop slows down over timeCheck unbounded arrays, repeated concatenation, plotting, file I/O, and stale sample handling.
Apparent phase target is inaccurateCheck causal estimator bias, filter delay, amplitude/SNR, output latency, display refresh, photodiode timing, and clock alignment.

MEGIN operator note: what it contributes

The uploaded local operator note (dated 2022) describes: launching neuromag2ft from a specific Linux directory; an example command ./neuromag2ft --chunksize 30; starting the stream when MEGIN Acquisition enters Go; stopping acquisition at the end of a run; stopping the bridge with Ctrl+C; and configuring internal stimulus generation for test triggers. These are useful local procedural notes, but they should be checked against the current MEGIN workstation image and local operator guidance.

Do not blindly copy the local trigger settings into a participant experiment. The note's internal trigger configuration is a test/operational procedure. Confirm the electrical output, polarity, channel, event code, and recording path with the MEG operator before using it for timing calibration.

Recommended development stages

  1. Confirm supported streaming route. Record MEGIN model, DACQ version, bridge type/version, operating system, and buffer host/port.
  2. Prove MATLAB connectivity. Header, sample count, a few channels, and events.
  3. Run FieldTrip examples. Signal viewer first, then power estimate.
  4. Build a minimal processor. RMS and alpha power, with sample-gap and run-reset handling.
  5. Measure timing. Block cadence, processing time, TTL, photodiode, end-to-end delay and jitter.
  6. Compare online/offline features. Establish agreement and characterize failure cases.
  7. Only then add closed-loop logic. Phase estimation, amplitude gating, prediction, and output control.
