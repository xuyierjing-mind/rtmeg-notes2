Part 02 · Getting started

Start real-time streaming from MEGIN

The first milestone is simple: start the bridge, start acquisition, and verify that MATLAB can read a growing stream. Do not add filtering or phase estimation until this works reliably.

Version check before proceeding. Your uploaded operator note describes neuromag2ft --chunksize 30. FieldTrip's current MEGIN documentation warns that this interface has compatibility issues on some TRIUX neo + newer DACQ combinations and points to an LSL-based alternative. Ask the local MEG operator which route is supported on your actual installation.

Legacy operator-note procedure (confirm locally)

Open the terminal in the directory containing the approved neuromag2ft executable.
Start the bridge. The local operator note gives this example:
./neuromag2ft --chunksize 30

The note was written for a 1000 Hz sampling rate and describes 30 samples as approximately 30 ms. It also says not to set the chunk size below 28 for that installation. This is a local, historical operating instruction—not a universal setting for all MEGIN systems or current bridge versions.

Chunk size in plain language: it is how many samples are sent together in one update. Smaller chunks can reduce waiting time, but may increase system load. The actual achievable update interval is also constrained by the MEGIN acquisition path and packetization. Do not force an arbitrarily small number; measure it.
In MEGIN Acquisition, press Go to start acquisition. In the local note, this is when the stream begins to be written to the buffer.
On the analysis computer, run the MATLAB connection test below.
At the end of a run, stop acquisition and follow the operator's local procedure for stopping or restarting the bridge. The operator note recommends restarting between runs for its legacy setup.

MATLAB: first connection test

Start MATLAB, add FieldTrip to the path, and initialize it once per MATLAB session.

addpath('C:/toolboxes/fieldtrip');  % change to your FieldTrip folder
ft_defaults;

dataset = 'buffer://localhost:1972'; % replace host if remote
hdr = ft_read_header(dataset);

disp(hdr.Fs)          % sampling frequency
disp(hdr.nChans)      % number of channels
disp(hdr.label(1:10)) % inspect some channel labels

If the buffer is on another computer, use e.g. buffer://meg-acq-pc:1972. The host name and port must match the bridge configuration.

Read the latest data

% Ask how many samples have arrived
hdr = ft_read_header(dataset);
lastSample = hdr.nSamples;

% Read a short recent segment (example: last 1 second)
nRecent = round(hdr.Fs);
begsample = max(1, lastSample - nRecent + 1);
endsample = lastSample;

dat = ft_read_data(dataset, ...
    'begsample', begsample, ...
    'endsample', endsample);

size(dat)  % channels x samples
Important: this is a one-time read example, not a continuous real-time loop. In a loop, track the last sample already processed and request only samples after it. Also check that the buffer has enough samples before requesting a block.

What success looks like

  • The header returns without an error.
  • The sampling rate and channel labels match the expected acquisition setup.
  • The latest sample count increases while acquisition is running.
  • Repeated reads return new data rather than the same block.
  • Events can be read when triggers are being generated.
