Part 05 · Closed-loop development

From online monitoring to a closed-loop experiment

Phase estimation is one possible online feature—not the purpose of the entire real-time system. The same pipeline can monitor alpha power, frequency, signal quality, head position, or other features.

Build in stages

Monitoring only. Display selected channels, events, and simple features. No output is sent.
Offline-to-online agreement. Apply the same feature definition to recorded data offline and compare it with the online result.
Shadow trigger. Let the algorithm decide when it would trigger, but do not send a physical output. Log every decision.
Bench test. Use a known periodic signal and record algorithm output, TTL, and (for visual experiments) photodiode onset.
Participant pilot. Only after stable bench validation, test the full setup under approved lab procedures.

Phase estimation: the special challenge

Offline Hilbert phase is commonly computed with filtering methods that use data on both sides of a time point. A real-time algorithm cannot use future samples. It must be causal, and its phase estimate at the current endpoint can be biased by filter transients and endpoint effects.

ApproachBasic ideaTrade-off
AR forecast + HilbertPredict a short segment into the future, then estimate phase away from the edge.Fast, but depends on forecast quality and signal-to-noise ratio.
State-space / Kalman oscillatorTrack a rotating latent state sample by sample.Can quantify uncertainty; needs sensible model fitting and validation.
Endpoint-corrected Hilbert / oscillator trackingCorrect or model endpoint behavior to estimate phase causally.Useful alternatives; implementation details and frequency assumptions matter.
PLLTrack phase/frequency relative to an internal oscillator.Simple online structure; tuning and lock behavior need validation.
Do not assume a single method is universally best. Compare candidate estimators using your own MEG recordings, realistic noise, transient alpha bursts, and known simulated signals. Quantify phase error and estimator uncertainty before enabling triggers.

Spatial filtering: prepare offline, apply online

MEG has many sensors. For a focused online feature, a precomputed spatial projection can reduce the sensor array to one or a few virtual channels. The projection should be derived using appropriate calibration/task data and then applied consistently online. Confirm channel order, units, bad-channel handling, and preprocessing compatibility. A spatial filter is not a generic noise-removal guarantee.

Visual stimulation: measure the light, not just the software call

  • Psychtoolbox's Screen('Flip') provides useful display timing information, but physical display onset depends on refresh timing, scan-out, and projector/display processing.
  • Use a photodiode at the participant-facing display and record its signal in MEGIN whenever feasible.
  • Record a hardware TTL marker as well, so software intent and physical display onset can be compared.
  • Measure the delay distribution over many trials; do not rely on a single calibration value.

Python later: add a client, not a second acquisition system

The FieldTrip buffer is a network protocol, not a MATLAB-only technology. Python can read a FieldTrip buffer using the available Python client, or a MEGIN-supported LSL stream can be read using MNE-LSL. Keep the acquisition path stable and add Python only when there is a concrete reason, such as an estimator or library that is easier to use there.
