Part 04 · Practical MATLAB examples

From a viewer to online features

Start by using FieldTrip's supplied examples. Then build your own processor in small steps. The examples below are templates: adapt channel labels, buffer host, and FieldTrip version to your installation.

Example A · Use the FieldTrip realtime signal viewer

The viewer is a useful first check because it confirms that data can be read and displayed without writing your own acquisition client.

cfg = [];
cfg.dataset = 'buffer://localhost:1972'; % or buffer://HOST:1972
ft_realtime_signalviewer(cfg);

The exact configuration options depend on the FieldTrip example and version. Use the linked official example as the source of truth for optional settings.

Example B · Online power estimate

Once the signal viewer works, try FieldTrip's realtime power-estimation example. It demonstrates the pattern of continuously updating a feature from newly arriving data.

cfg = [];
cfg.dataset = 'buffer://localhost:1972';
% Add only the options documented for your FieldTrip version.
ft_realtime_powerestimate(cfg);

Example C · Your own minimal rolling processor

This deliberately simple template reads newly arrived data and computes a rolling RMS value. It does not filter, reject artifacts, estimate phase, or send triggers. It is intended to teach the data-flow pattern.

ft_defaults;
dataset = 'buffer://localhost:1972';

hdr = ft_read_header(dataset);
fs = hdr.Fs;
nChans = hdr.nChans;

lastSample = 0;
windowSeconds = 1;
windowSamples = round(windowSeconds * fs);

while true
    % Refresh the header to learn how many samples are available
    hdr = ft_read_header(dataset);
    newestSample = hdr.nSamples;

    if newestSample > lastSample
        % Read only the samples that have arrived since last iteration
        newData = ft_read_data(dataset, ...
            'begsample', lastSample + 1, ...
            'endsample', newestSample);

        lastSample = newestSample;

        % Maintain a short rolling buffer for each channel
        if ~exist('rollingData','var')
            rollingData = zeros(nChans, 0);
        end
        rollingData = [rollingData, newData];

        % Keep only the most recent window
        if size(rollingData,2) > windowSamples
            rollingData = rollingData(:, end-windowSamples+1:end);
        end

        % Example feature: RMS per channel (not band-limited power)
        if size(rollingData,2) == windowSamples
            rmsValue = sqrt(mean(rollingData.^2, 2));
            % Update a display or save to an in-memory log here
        end
    else
        pause(0.005); % short idle wait; tune after measuring update cadence
    end
end
Before using this as an experiment loop: add error handling, stop conditions, buffer reset/run handling, sample-gap checks, bounded memory, and logging. Avoid frequent plotting or disk writes inside the time-critical path. The example uses a simple polling pattern; the right poll interval should be chosen from measured data arrival behavior.

Good habits for MATLAB loops

  • Read only samples that have not yet been processed.
  • Track sample indices; do not rely only on wall-clock time.
  • Check for gaps, resets, or a new run before updating the state.
  • Preallocate arrays where possible and keep memory bounded.
  • Separate acquisition, processing, visualization, and output into clear functions.
  • Do not treat successful plotting as evidence of low latency.
